# 06. Motivation Engine — 動機を内製する仕組み（インディーハッカー特化）

> killshot #1（動機の逆説）への直接の回答。
> 「ユーザーのやる気が切れた木曜の夜に、開かれるか？」に **Yes** と言えるための中核サブシステム。

自己モデル（オントロジー）は**武器**であって**動機**ではない。
本エンジンは、選定ウェッジ（**ソロ起業家 / インディーハッカー**）の動機構造に合わせて、動機を外から供給せずに**製品の中で内製**する。

---

## 1. なぜインディーハッカーか（動機構造の一致）

インディーハッカーのやる気を殺す要因は明確で、本製品の設計と噛み合う:

| やる気を殺す要因 | 本製品での対抗策 |
| --- | --- |
| **孤独**（一人で作る、伴走者がいない） | Twin が文脈を全部知った上で毎日伴走・週次でコミットを預かる |
| **前進が見えない**（地味な作業の連続、成果が遅延） | 出荷ログ・streak・「過去の自分との差分」を可視化 |
| **外部アカウンタビリティの欠如**（誰も締切を課さない） | 週次コミット儀式＋フォロー、任意で build-in-public に外部化 |
| **成果が埋もれる**（作っても誰も見ない） | ログが changelog / weekly update / ポートフォリオに結晶化し外に出る |

インディーハッカーは元々「出荷する（ship）」文化を持つ。**出荷を軸に動機を組める**のがこのセグメントの強み。

---

## 2. 理論的下敷き

- **自己決定理論（SDT）**: 動機は Autonomy（自律）× Competence（有能感）× Relatedness（つながり）で内発化する。→ 3 つすべてを設計に埋める。
- **Tiny Habits（BJ Fogg）**: やる気が低い時は行動のハードルを下げる。B = MAP（Motivation × Ability × Prompt）。動機が落ちたら Ability を上げる（＝小さくする）。
- **Commitment & Consistency（Cialdini）**: 自ら宣言した約束は守られやすい。週次コミットを本人の言葉で。
- **Progress Principle（Amabile）**: 小さな前進の可視化が、内発的動機の最大のドライバ。

---

## 3. 4 つの動機メカニズム（製品の背骨）

### M1. Momentum を可視化する（Competence）
- **Ship Streak**: 「ToBe に向けて出荷した回数」の連続記録。単なるログイン streak ではなく**前進の streak**。
- **過去の自分との差分**: 「3週間前のあなたは〇〇。今のあなたは△△」というナラティブ。インディーハッカーは"進化の物語"に反応する。
- **Gap の縮小カーブ**: 選んだ ToBe（例:「v1 をローンチ」）への距離が縮む様子を1本の線で。

### M2. アカウンタビリティ・ループ（Relatedness / Commitment）
- **週次コミット儀式**: 毎週「来週、出荷する"たった1つ"」を本人の言葉で宣言 → Twin が預かる。
- **フォロースルー**: 週の途中と週末に「あのコミット、どう？」を文脈込みで。詰めない、伴走する。
- **任意の外部化**: build-in-public 派には、コミットと成果を小さな輪 / X に出すオプション（後述の M3 と一体）。

### M3. 有形の産出物（Competence + Distribution）
- 日々のログ・振り返りが、**自動で weekly update / changelog / ポートフォリオ**に結晶化。
- それが**外に出せる**（build-in-public の投稿ドラフト）。
- → これは同時に **獲得の成長ループ**になる: 産出物がシェアされる → 新規流入。GTM と動機設計が一体化する。

### M4. 「木曜の夜」フェイルセーフ（Autonomy + Tiny Habits）
- ドリフト / バーンアウト / 未オープンを検知したら、**要求を最小化**する。詰めない・恥をかかせない。
- 例:「今日は1行だけ。何に詰まってる？」/「休んでいい。1つだけ、明日の自分に楔を打つなら？」
- **やる気が最も枯れた瞬間にこそ、ハードルを下げて再入場（re-entry）を設計する**。ここが勝敗の分岐点。

---

## 4. Motivation State Machine（介入の姿勢を状態で切り替える）

Functions（`momentum` / `drift_risk` / `burnout_signal` / 最終オープン）からユーザーの**動機状態**を推定し、
エージェントの**姿勢（posture）**を切り替える。同じ状況でも姿勢が違えば言葉が変わる。

| 状態 | 推定シグナル | 姿勢（Posture） | エージェントの振る舞い |
| --- | --- | --- | --- |
| **Flowing**（乗っている） | 高 momentum・連続出荷 | **Celebrate + Stretch** | 勝ちを祝い外に出す。ほんの少し bar を上げる |
| **Coasting**（惰性） | 中 momentum・停滞気味 | **Focus** | 「今日の1つ」に集中を促す軽いナッジ |
| **Drifting**（逸れ） | drift_risk 上昇・コミット未達 | **Re-anchor + Shrink** | ToBe/価値観に再接続し、行動を小さく割る |
| **Stalled**（未オープン数日） | 最終オープンが古い | **Thursday-night failsafe** | 最小・恥フリーな再入場。1行だけ |
| **Burnt**（消耗） | burnout_signal・過密・ネガ気分 | **Protect** | 休む許可・目標を一時縮小・つながりの確認 |

> 実装は `src/core/functions.ts` の `motivationState()` と、`src/agents/coach.ts` の posture 別テンプレに対応。

---

## 5. North Star との接続（測定可能に）

- **North Star（インディーハッカー版）**:
  「**週次で"前進した実感" × 実際の出荷/収益/学習アウトプット**」。
- 先行指標:
  - **Weekly Commit 実施率** と **達成率**（アカウンタビリティが効いているか）
  - **Ship Streak の継続**（動機の内製が起きているか＝木曜の夜に開かれたか）
  - 産出物の**外部シェア率**（M3 が獲得ループになっているか）
  - **Stalled → 再入場率**（フェイルセーフが機能しているか）
- これらが立てば「動機を内製できた」＝**継続課金の根拠**になる。

---

## 6. 反証と注意（過信しないために）

- **依存を作らない**: SDT の Autonomy を守る。Twin は「代わりに決める」のではなく「本人が決めるのを助ける」。
- **メンタル領域のフェイルセーフ**: Burnt を超える兆候（抑うつ等）は助言せず適切なリソースへ。
- **ゲーム化の罠**: streak のための streak にしない。常に「本物の前進（出荷/収益/学習）」に接続する。
- **検証すべき仮説（再掲）**: Wizard-of-Oz 4週間で **Stalled からの再入場が起きるか** が、このエンジンの成否の一次証拠。
